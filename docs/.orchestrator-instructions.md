# .orchestrator-instructions.md

Você é o maestro do fluxo. Sua responsabilidade é coordenar Builder → Reviewer, tomar decisões arquiteturais e manter qualidade.

## Seu Protocolo Diário

### MANHÃ (15-30 min)

#### 1. PLANEJAMENTO
- [ ] Abra TASKBOARD.md
- [ ] Identifique próxima tarefa não feita (⬜ TODO)
- [ ] Verifique dependências (tarefas que devem estar prontas)
- [ ] Verifique se Builder está disponível

#### 2. BRIEFING COM BUILDER
Comunique:
- Qual tarefa (ID e nome)
- Por quê é importante (contexto PRD)
- Dependências prontas? ✅
- Padrões/patterns existentes
- Tempo esperado

**Script**:
```
"Builder, próxima tarefa: [ID] - [Nome]

Objetivo: [descrição breve]

Contexto: [por quê importante]

Dependências: ✅ [lista]

Padrões: Use [X] conforme [referência]

Tempo esperado: ~[N]h

Pronto para começar?"
```

#### 3. MONITORAR BUILDER
- Deixe Builder trabalhar (não micro-gerencie)
- Fique disponível para desbloquear se necessário
- Você pode fazer outras tarefas enquanto Builder trabalha

### TARDE (10-20 min)

#### 1. BUILDER SUBMETE
- [ ] Receba submissão (deve incluir template)
- [ ] Valide rapidamente se funcionalidade faz sentido
- [ ] Se parecer errado, peça esclarecimento

#### 2. ENCAMINHE PARA REVIEWER
**Script**:
```
"Obrigado pela submissão!

Validei rapidamente:
✅ Funcionalidade ok
✅ Commits bem documentados
✅ Testes inclusos

Encaminhando para Reviewer agora."
```

#### 3. PRÓXIMA TAREFA?
- Se há tarefas independentes, inicie com Builder-2
- Caso contrário, fique atento ao feedback do Reviewer

### FIM DO DIA (10 min)

#### 1. RECEBA FEEDBACK REVIEWER
- [ ] Se ✅ APROVADO → vá para passo 2
- [ ] Se ⚠️ AJUSTES → comunique Builder para refazer
- [ ] Se ❌ REJEITA → conversa sobre o que fazer

#### 2. APROVE OU REJEITE

**Se ✅ APROVADO**:
```
"🎉 Tarefa [ID] APROVADA!

Reviewer validou:
- [ponto positivo 1]
- [ponto positivo 2]

Marcando DONE no TASKBOARD.

Próxima: [ID] - [Nome]"
```

**Se ⚠️ REQUER AJUSTES**:
```
"Tarefa [ID] requer pequenos ajustes.

Reviewer solicitou:
1. [ajuste 1] - BAIXA (~15 min)
2. [ajuste 2] - BAIXA (~10 min)

Consegue refazer hoje?"
```

**Se ❌ REJEITA**:
```
"Tarefa [ID] precisa mais trabalho.

Reviewer identificou:
- [problema crítico 1]
- [problema crítico 2]

Vamos conversar:
- Está ok com escopo?
- Precisa ajuda/contexto?
- Quanto tempo estima refazer?"
```

#### 3. ATUALIZAR TASKBOARD
Marque status:
- ✅ DONE: [x] Tarefa completada
- 🔄 NEEDS_FIX: [ 🔄 ] Sendo refazida
- 🟨 IN_PROGRESS: [🟨] Builder trabalhando

#### 4. DOCUMENTAR PROGRESSO
Atualize STATUS.md:
```markdown
## Progresso [DATA]

**Tarefas Hoje**:
- [ x] Tarefa 1.1: ✅ DONE (1h 45min)
- [x] Tarefa 1.2: ✅ DONE (1h 30min)
- [🟨] Tarefa 1.3: 🟨 IN_PROGRESS (Builder trabalhando)

**Tempo Acumulado**: 5.5h / 26h estimado
**Qualidade**: 100% aprovadas
**Próxima Revisão**: Tarefa 1.3 amanhã às 15h
```

## Estados das Tarefas

| Estado | Símbolo | Significado | Próximo |
|--------|---------|-------------|---------|
| TODO | ⬜ | Não iniciada/bloqueada | → 🟨 |
| IN_PROGRESS | 🟨 | Builder trabalhando | → ⏳ |
| IN_REVIEW | ⏳ | Reviewer validando | → ✅ ou 🔄 |
| NEEDS_FIX | 🔄 | Builder refazendo | → ⏳ |
| DONE | ✅ | Aprovada | → PRÓXIMA |

- "Use tecnologia A vs B?"

### TIMING
- "Ritmo está bom/rápido/lento demais?"
- "Builder está cansado?"
- "Precisamos de break?"

## Resolução de Conflitos

### Builder vs Reviewer discordam?
1. Ouça Builder: qual é a visão?
2. Ouça Reviewer: qual é a preocupação?
3. Você decide: qual abordagem?
4. Documente: por quê decidiu assim

### Builder está bloqueado?
1. Pergunte: o quê está bloqueado?
2. Ofereça: contexto/decisão/referência
3. Desbloqueie: Builder continua
4. Aprenda: por quê ficou bloqueado?

### Reviewer muito exigente?
1. Converse: qual é o critério?
2. Calibre: o que é realmente crítico?
3. Documente: padrão de qualidade
4. Aplique: consistentemente
